# Microsoft Entra External ID browser-delegated sign-in (iOS / Objective-C)

The Objective-C sample now has a second, independent Microsoft Entra External ID browser sign-in path. The existing workforce client ID, account key, and sign-in path remain in place. Both flows use MSAL public-client APIs; the sample does not implement a parallel OAuth flow.

For a staging sign-in option through WorkOS AuthKit, see [WorkOS federation setup](WORKOS_AUTHKIT_ENTRA_EXTERNAL_ID.md).

## Scope and security model

- The app is a native **public client**. Do not embed a client secret or private key.
- Microsoft Entra hosts the sign-in and sign-up page; the app presents the system browser through MSAL.
- MSAL owns the authorization-code flow, PKCE, state/nonce validation, token exchange, and token-cache integration. Do not implement a second code exchange in the app.
- Use the External ID customer tenant authority: `https://<tenant-subdomain>.ciamlogin.com/`.
- This guide is for browser-delegated authentication. Do not enable native authentication merely to use this flow.

## 1. Register the iOS application

In the **External ID customer tenant** (not a workforce tenant):

1. Create or select the app registration.
2. Add the **iOS / macOS** platform and enter the exact bundle identifier used by the sample target.
3. Copy the redirect URI generated by the platform configuration. Use that exact URI in the app configuration and URL scheme registration; do not construct a different URI by hand.
4. Configure a sign-up and sign-in user flow and attach the app to that flow.
5. Add only the delegated API permissions the app actually needs. For Microsoft Graph, request Graph scopes only if this sample calls Graph.
6. Do not enable **Allow public client flows** solely for browser-delegated sign-in. That setting is not required for this approach.

Required values:

| Setting | Value |
|---|---|
| Client ID | Application (client) ID from the External ID registration |
| Authority | `https://<tenant-subdomain>.ciamlogin.com/` |
| Redirect URI | Exact URI generated for the iOS / macOS platform |
| Bundle ID | Exact bundle identifier registered in the tenant |
| Scopes | API scopes exposed/consented for this client |

The client ID, authority, redirect URI, and scopes are configuration, not secrets. Never add client secrets, passwords, tokens, authorization codes, or private keys to the app or repository.

## 2. Configure the Objective-C sample app

The Objective-C sample reads `ExternalIDClientId`, `ExternalIDAuthority`, and `ExternalIDScopes` from its Info.plist. The committed values are safe placeholders and intentionally prevent sign-in until configured. For a local test, replace them in a local build configuration or Info.plist with the application (client) ID, `https://<tenant-subdomain>.ciamlogin.com/`, and at least one delegated scope exposed by the API. Keep tenant-specific values out of commits.

The sample reads its bundle identifier from the built app and derives the default redirect URI as `msauth.<bundle-id>://auth`. The existing URL type now expands the same bundle identifier, preserving the workforce scheme while registering the External ID callback. If your tenant registration supplies a different redirect URI, set `ExternalIDRedirectUri` in the app configuration and register its scheme. The sample validates HTTPS authority, the CIAM host, a configured client ID, nonempty scopes, and a registered `auth` callback before creating the External ID MSAL client.

The login view has separate workforce and External ID buttons. External ID stores its account identifier under its own key, uses the configured scopes for silent acquisition, and starts an interactive request only for `MSALErrorInteractionRequired`. The UI suppresses the expected user-cancelled error. External ID sign-out removes that account from this client's MSAL cache; it does not claim to terminate every system-browser SSO session.

## 3. Initialize MSAL with the External ID authority

The following uses public APIs present in this repository:

```objective-c
#import <MSAL/MSAL.h>

static NSString * const kExternalIDClientId = @"<APPLICATION_CLIENT_ID>";
static NSString * const kExternalIDAuthority = @"https://<TENANT_SUBDOMAIN>.ciamlogin.com/";
static NSString * const kExternalIDRedirectUri = @"<EXACT_REGISTERED_REDIRECT_URI>";

- (MSALPublicClientApplication *)createExternalIDApplication:(NSError **)error
{
    NSURL *authorityURL = [NSURL URLWithString:kExternalIDAuthority];
    if (!authorityURL || ![authorityURL.scheme.lowercaseString isEqualToString:@"https"])
    {
        if (error)
        {
            *error = [NSError errorWithDomain:@"ExternalIDSample"
                                         code:1
                                     userInfo:@{NSLocalizedDescriptionKey: @"The External ID authority must be a valid HTTPS URL."}];
        }
        return nil;
    }

    NSError *authorityError = nil;
    MSALAuthority *authority = [MSALAuthority authorityWithURL:authorityURL error:&authorityError];
    if (!authority || authorityError)
    {
        if (error) *error = authorityError;
        return nil;
    }

    MSALPublicClientApplicationConfig *config =
        [[MSALPublicClientApplicationConfig alloc] initWithClientId:kExternalIDClientId
                                                        redirectUri:kExternalIDRedirectUri
                                                          authority:authority];

    return [[MSALPublicClientApplication alloc] initWithConfiguration:config error:error];
}
```

Do not add the tenant's OpenID Connect discovery URL as the authority. MSAL resolves metadata from the authority. Confirm the tenant subdomain and redirect URI from the External ID app registration/quickstart.

## 4. Start browser-delegated sign-in

Call this from a user-initiated action while the presenting view controller is visible. Replace the scope placeholder with a real delegated scope exposed by the API this app calls.

```objective-c
- (void)signInFromViewController:(UIViewController *)presentingViewController
                         scopes:(NSArray<NSString *> *)scopes
                      completion:(void (^)(MSALResult *result, NSError *error))completion
{
    NSError *creationError = nil;
    MSALPublicClientApplication *application =
        [self createExternalIDApplication:&creationError];

    if (!application)
    {
        completion(nil, creationError);
        return;
    }

    MSALWebviewParameters *webParameters =
        [[MSALWebviewParameters alloc]
            initWithAuthPresentationViewController:presentingViewController];

    MSALInteractiveTokenParameters *parameters =
        [[MSALInteractiveTokenParameters alloc] initWithScopes:scopes
                                             webviewParameters:webParameters];

    [application acquireTokenWithParameters:parameters
                            completionBlock:^(MSALResult *result, NSError *error)
    {
        if (error)
        {
            // Treat user cancellation as cancellation; do not log tokens or codes.
            completion(nil, error);
            return;
        }

        // Persist the account identifier if the app needs to select this account later.
        // Never persist the access token in UserDefaults or write it to logs.
        completion(result, nil);
    }];
}
```

MSAL uses the platform system browser by default. Do not replace it with an embedded `WKWebView` for this flow; system-browser authentication preserves the expected browser SSO behavior.

## 5. Forward the redirect callback to MSAL

In the app delegate, forward the callback URL to MSAL. Do not parse the authorization code yourself and do not route this callback through a password-reset or device-pairing handler.

```objective-c
- (BOOL)application:(UIApplication *)app
            openURL:(NSURL *)url
            options:(NSDictionary<UIApplicationOpenURLOptionsKey, id> *)options
{
    BOOL handled =
        [MSALPublicClientApplication
            handleMSALResponse:url
            sourceApplication:options[UIApplicationOpenURLOptionsSourceApplicationKey]];

    return handled;
}
```

If the app uses scenes, forward the URL from the corresponding scene URL callback using the app's existing lifecycle routing. Do not remove existing URL handlers; ensure MSAL receives its registered callback.

## 6. Acquire tokens silently after sign-in

Use the account returned by MSAL and the same tenant-specific application configuration:

```objective-c
MSALSilentTokenParameters *parameters =
    [[MSALSilentTokenParameters alloc] initWithScopes:scopes account:account];

[application acquireTokenSilentWithParameters:parameters
                              completionBlock:^(MSALResult *result, NSError *error)
{
    if (error)
    {
        // If MSAL reports MSALErrorInteractionRequired, start a new
        // user-initiated interactive request. Do not retry silently in a loop.
        completion(nil, error);
        return;
    }

    completion(result, nil);
}];
```

Handle `MSALErrorInteractionRequired` by presenting an interactive request in an appropriate user context. Handle cancellation separately from authentication failure. Request the least-privilege scopes required by the target API.

## 7. Sign-out behavior

Use MSAL's account removal/sign-out APIs for the selected account and configured application. A local cache removal is not proof that every upstream browser session or other application session has ended. If the product requires browser-session sign-out, use MSAL's supported sign-out API with the appropriate sign-out parameters and explain the scope of sign-out in the UI.

## 8. Validation checklist

- [ ] Build the existing iOS sample target with no tenant-specific values committed.
- [ ] Confirm the authority is the exact External ID customer tenant `ciamlogin.com` host.
- [ ] Confirm the registered redirect URI, app URL scheme, and bundle ID match exactly.
- [ ] Complete interactive sign-in and sign-up with a customer identity in the External ID tenant.
- [ ] Confirm the callback is handled by MSAL and no app code exchanges the authorization code.
- [ ] Acquire a token for the intended API scope and validate its audience at that API.
- [ ] Acquire a token silently for the signed-in account.
- [ ] Verify interaction-required, user-cancelled, network-error, and invalid-configuration handling.
- [ ] Verify account removal/sign-out behavior and document the remaining browser SSO session behavior.
- [ ] Run the repository's existing iOS/macOS CI workflows on supported Apple runners.

## 9. Boundaries and known prerequisites

Objective-C XCTest cases exercise fail-closed configuration validation, bundle-derived redirects, unregistered schemes, and callback routing boundaries. The Apple CI workflow runs the MSAL iOS unit-test target and builds the Objective-C sample. Live validation requires a real External ID customer tenant, app registration, bundle identifier, redirect URI, user flow, test customer, and API scope. Do not mark tenant authentication as verified until those tests have been run.

This integration does not add passkey/WebAuthn APIs to MSAL. Passkey support is configured and performed by the identity provider's hosted experience where supported. It also does not make MSAL's iOS interactive API a device-authorization API.
